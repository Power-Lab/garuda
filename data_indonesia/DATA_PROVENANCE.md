# Data provenance

Where every input dataset comes from, how it was made, what has been changed
since, and which official source is meant to replace it. The datasets are
**research-grade**: credible, structured for the model, and traceable — but not
yet drawn from official published sources. This file is the traceability record;
the upgrade path to decision-grade data is the replacement map at the bottom.

*Every claim here is checkable: lineage via `git log --follow <file>`,
byte-identity via `cmp`, flag consistency via `tools/validate_schema.py`.*

## Lineage in one paragraph

Everything descends from the repository's initial snapshot (commit `65b57d8`),
a fork of **`village-indonesia-100gw@1096aa4`** — the IESR / UC San Diego Power
Transformation Lab study behind Indonesia's 100 GW village-solar programme. The
**grid-side files descend from the
[Power-Lab/data-indonesia-2025](https://github.com/Power-Lab/data-indonesia-2025)
release** (MIT; the data behind the captive-indonesia-2025 study,
[report on Zenodo](https://zenodo.org/records/17345968)) — verified by `cmp`
across every shared grid file for all seven overlapping islands in both years, until
the investment costs were annualised (see the log). That repository is being archived;
these copies are now the maintained data.
Since the snapshot, this repository has made these classes of data change, each
listed in the modification log below: RE-flag corrections, hubdist-based
connection costs, the synthetic demo case, and priced village battery power, plus
the annualisation of the island datasets' overnight investment costs.

## Known quirks (documented, deliberately not "fixed")

- **maluku `plts_buia` appears twice** (upstream naming): R_ID 16 is a genuine
  5 MW solar unit (solar CF profile, mean 0.14); R_ID 17 is a 3 MW **gas engine**
  carrying a solar-style name (flat availability, gas fuel, gas-engine costs).
  The audit corrected R_ID 17's RE flag; the misleading name is left as imported
  so the row remains traceable to upstream.
- **`Sub_Weights` are non-uniform for maluku** (2022/505/…), so representative-
  period energy sums annualise only approximately there — see the note in
  [`docs/outputs_guide.md`](../docs/outputs_guide.md).
- **ERA5-derived solar profiles are coarser than 780 villages.** ERA5's grid is
  ~28 km, and **153 of the 780 villages carry no coordinates** in
  `timor_villages_manifest.csv` (`lat`/`lon` blank for exactly 153 rows) — they all
  fall back to the island centroid of the located ones, `(-9.69766, 124.36616)`,
  and therefore sample one identical ERA5 cell. So a high inter-village capacity
  factor correlation is **partly a data artifact** and must not be presented as
  evidence that village solar output is genuinely coincident across Timor. The
  wiring tool (`tools/ntt/wire_era5_solar.py`) reports the number of distinct
  profiles it wired for exactly this reason.
- **`build_timor.py` no longer byte-reproduces the committed `timor` folder**, so
  the battery-power change above was applied as a targeted column patch rather
  than by regenerating. Measured 2026-07 (`--src-dir` pointed at the committed
  workbooks, no `--solar-cap`), three files differ from a fresh build:
  - `village_generators.csv::Max_Cap_MW` — the committed file carries the GIS
    solar ceilings (174–4692 MW/village); a build without `--solar-cap` writes 0.
    Regenerating without the QGIS layers **silently discards** those ceilings.
  - `village_demand.csv` — 3 of 780 villages (`village222`, `village279`,
    `village291`) differ by up to 41 %, and they are fishing-archetype rows in the
    committed file but not in a fresh build (7 vs 4 fishing battery rows). The
    archetype assignment has drifted since the folder was built. System-wide the
    effect is small: 544.08 vs 543.32 GWh/yr (0.14 %), coincident peak 128.24 vs
    128.12 MW, and `generators.csv`'s PLN diesel 122.131 vs 122.023 MW follows.
  - `village_connection.csv` — expected: the committed file is the `hubdist_km`
    rederivation (`d04184d`), while `build_timor.py` writes its provisional
    centroid-distance values. Rerunning the build reverts that fix.
  Reproducing the committed folder therefore needs `--solar-cap` plus the GIS
  layers, `tools/connection_cost.py` re-applied, and the archetype drift resolved.
- **The committed source workbooks are the *translated* copies.**
  `source_ntt/english/` holds `Village_Potential_Data_EN.xlsx` /
  `NTT_Village_Dataset_EN.xlsx`, but `build_timor.py` opens the original
  Indonesian filenames (`Data potensi desa.xlsx`, `NTT_Data_Desa.xlsx`), so the
  documented command fails on a fresh clone until the files are renamed. The
  translated workbooks do load correctly once renamed.
- **Fuel prices and technology costs** are the upstream study's assumptions
  (`fuels_data.csv`, generator cost columns) and have not been revalidated here.
  NTT-specific cost assumptions used for the Timor build are in
  [`tools/ntt/costs.py`](../tools/ntt/costs.py), each overridable.

## Replacement map: research-grade → decision-grade

A decision-grade study replaces these inputs island-by-island. What replaces
what:

| Input | Official source to substitute |
|---|---|
| `generators.csv` (fleet, candidates, costs) | **PLN RUPTL** project lists + published technology cost benchmarks |
| `network.csv` (inter-zonal limits) | **PLN RUPTL** transmission plan |
| `demand.csv` (zonal demand, growth) | **ESDM / RUKN** demand projections |
| `village_demand.csv` + electrification status | **BPS Podes** / PLN electrification data + partner surveys (the NTT workbooks are the template) |
| `fuels_data.csv` (prices, emission factors) | **ESDM** fuel price benchmarks; IPCC emission factors |
| `village_connection.csv` unit costs | **PLN** MV-line and connection unit costs (flags on `tools/connection_cost.py`) |

The schema is unchanged by substitution: drop replacement CSVs into a folder and
`tools/validate_schema.py` + `run_model.jl --preflight-only` will gate them.
